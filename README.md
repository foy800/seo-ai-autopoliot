# seo-agent-ru

Универсальный автономный SEO-агент под Яндекс для русскоязычных сайтов. Берёт запросы из очереди,
пишет по 3 статьи в день, проверяет каждую скриптом, делает обложку без текста и публикует
на обычный сайт без CMS по FTP. Подходит для любой тематики. Работает на сервере по cron
или как скилл Claude Code.

## Что умеет

- **Ведёт контент-план в Excel** (`content-plan.xlsx` в папке проекта, создаётся сам): заголовок и ключ напротив
  друг друга, колонка «Одобрено», статус «ожидается» или «готова», дата публикации и ссылка.
- **Публикует только одобренное, и это жёсткий запрет:** пока вы сами не поставили «да» в колонке «Одобрено», статья не пишется и не выходит, даже если об этом попросить в чате.
- **Заголовок к каждому ключу, без группировки и отбора.** Предупреждает о каннибализации и уже существующих страницах, но решение оставляет человеку.
- **Пишет статьи** через OpenAI по вашему плану запросов: ключи в заголовке и тексте, перелинковка,
  таблицы, списки, врезки («Важно!», «Обратите внимание!»), вступление и вывод по 2-3 предложения.
- **CTA из страницы услуги:** в конце статьи агент описывает подходящую услугу по её описанию из
  `context/pages.csv` и ставит ссылку на неё. Телефон, имена и регалии не указываются.
- **Проверяет каждую статью** скриптом и переделывает до 3 раз. Не прошла: статус `failed`, на сайт не уходит.
- **Убирает ИИ-слоп** по правилам [humanizer-ru](https://github.com/ilyautov/humanizer-ru) и делает корректуру.
- **Делает обложку** через OpenAI: без текста, букв, логотипов и водяных знаков.
- **Публикует** страницу статьи, список статей и `sitemap-blog.xml` по FTP. Сбой не теряет статью: она
  публикуется при следующем запуске.
- **Ставится одной командой** на сервер, все секреты и параметры лежат в одном файле `.env`.

## Агент должен работать на сервере каждый день

Скилл считается настроенным только после развёртывания на сервере с ежедневным запуском (cron).
Без сервера настройка не завершена: агент обязан запросить у вас адрес и доступ к серверу
(`SSH_HOST`, `SSH_USER`, `SSH_KEY_PATH` или `SSH_PASS`, `SSH_REMOTE_DIR`, каталог сайта) и остановиться,
пока их нет. Секреты вписываются только в `.env`, не в чат. Развёртывание:
`python3 scripts/deploy.py --cron`, затем на сервере в `.env` нужен `OPENAI_API_KEY`.

**Приоритет правил.** Жёсткие: гейт «да», секреты в `.env`, никаких выдуманных фактов. Задание человека
выше мягких стилевых правил: если лимиты повторов ключей, каннибализация или длинные ключи
противоречат друг другу, статья всё равно пишется, а агент даёт предупреждение и рекомендацию.
Лимиты повторов ключей в `article_check.py` теперь предупреждения, а не блокировка.

## Установка на сервер

```bash
git clone https://github.com/foy800/seo-ai-autopoliot.git ~/seo-agent-ru && cd ~/seo-agent-ru && bash install.sh
```

Скрипт создаёт `config.json`, `.env` и рабочие файлы из шаблонов. Нужен только Python 3.9+,
для Excel нужен пакет openpyxl (установщик ставит его сам). Чтобы сразу включить ежедневный запуск в 07:00:

```bash
bash install.sh --cron
```

Обновление: `cd ~/seo-agent-ru && git pull`. Ваши `config.json`, `.env`, очередь и
логи остаются на месте, в репозиторий они не попадают.

## Залить на сервер одной командой с вашего компьютера

Если у вас есть SSH-доступ к серверу, заполните в `.env` блок «Доступ к серверу (SSH)»
(`SSH_HOST`, `SSH_USER`, `SSH_KEY_PATH` или `SSH_PASS`, `SSH_REMOTE_DIR`) и выполните
в папке скилла:

```bash
python3 scripts/deploy.py --dry-run   # проверить, что будет сделано, ничего не отправляя
python3 scripts/deploy.py             # залить скилл вместе с .env и запустить установку
python3 scripts/deploy.py --cron      # то же плюс ежедневный запуск в 07:00
```

Нужны `ssh` и `tar` (есть в Windows 10/11, Linux и macOS). Надёжнее вход по ключу; вход по
паролю работает только при установленном `sshpass`. Вместе со скиллом на сервер уходит и ваш
`.env`, поэтому используйте только свой сервер.

## Настройка

Все секреты и параметры лежат в одном файле **`.env`** (шаблон `templates/.env.example`,
установщик копирует его сам). Откройте и заполните:

```bash
nano .env
```

- **Секреты:** `OPENAI_API_KEY`, `FTP_HOST`, `FTP_USER`, `FTP_PASS`. В чат и в репозиторий
  их не отправляйте.
- **Сайт:** `SEO_SITE_URL`, `SEO_SITE_NAME`, `SEO_FTP_DIR` (папка сайта на сервере, например `/domain.ru/public_html`).
- **Объём и качество:** `SEO_DAILY_LIMIT`, `SEO_MIN_CHARS`, лимиты ссылок и ключей.
  Каждая переменная `SEO_<ПАРАМЕТР>` перекрывает одноимённое значение в `config.json`.
  Пустая строка означает «взять из `config.json` или значение по умолчанию».
- Модели OpenAI меняются переменными `OPENAI_TEXT_MODEL` и `OPENAI_IMAGE_MODEL`,
  актуальные названия смотрите в документации OpenAI.

Остальные файлы:

1. **`context/pages.csv`:** страницы сайта (`url,title,keywords,description,cta`). Из них берутся ссылки для
   перелинковки. Страницы услуг помечайте `cta=yes` и пишите для них `description`: агент выберет ближайшую
   по теме услугу, опишет её в финальном CTA по вашему описанию и поставит ссылку. URL, телефон и регалии
   вводить не нужно.
2. **`context/facts.md`:** единственный источник цен, имён и сроков.
3. **Запросы:** впишите их прямо в `content-plan.xlsx` (колонка «Основной ключ») или в `state/queue.csv`:
   новые запросы из CSV агент добавляет в таблицу сам.
4. Проверка ключа: `python3 scripts/openai_client.py check`.
5. Пробный прогон без ключа и без сети: `python3 scripts/pipeline.py --mock`
   (при `SEO_PUBLISH_MODE=ftp` без FTP статья получит статус `ready`, это нормально).

`config.json` можно не править: он нужен, только если вы хотите держать параметры не в `.env`.

## Запуск

```bash
python3 scripts/pipeline.py            # до daily_limit статей за сегодня
python3 scripts/pipeline.py --count 1  # одна статья
```

Повторный запуск в тот же день лимит не превысит.

## Контент-план в Excel и одобрение

При первом запуске агент **сам создаёт `content-plan.xlsx`** в папке проекта: переносит туда ваши запросы
и подбирает к каждому заголовок. Дальше работа идёт так:

1. Вы открываете таблицу, читаете заголовки, при желании правите их.
2. В колонке **«Одобрено»** ставите «да» у статей, которые можно писать и публиковать.
3. При следующем запуске агент пишет и публикует **только одобренные** статьи, до `daily_limit` в день.
   Неодобренные остаются «ожидается» и не трогаются.
4. После публикации агент ставит в таблице статус «готова», дату публикации и ссылку.

| Колонка | Кто заполняет | Что значит |
|---|---|---|
| Заголовок | агент, вы можете править | H1 статьи; в статье используется дословно |
| Основной ключ, Доп. ключи, LSI-слова | вы | задание для статьи |
| Тип, Лимит знаков, Тема, Приоритет | вы | информационный или коммерческий текст, лимит для коммерческого |
| **Одобрено** | **вы** | «да» разрешает писать и публиковать |
| **Статус** | агент | «ожидается» (не опубликована), «готова» (опубликована), «ошибка» (причина в «Примечании») |
| **Дата публикации** | агент | дата выхода статьи на сайт |
| Ссылка, Файл, Примечание | агент | адрес на сайте, файл статьи, пояснения |

Новые запросы дописывайте строками в конец листа «План» (достаточно основного ключа). Закрывайте файл
в Excel перед запуском агента: если он открыт, агент сохранит изменения в файл «content-plan (новый).xlsx».
**Это жёсткий запрет, отключить его нельзя.** Параметра `SEO_REQUIRE_APPROVAL` больше нет. Проверка
`scripts/gate.py` стоит в конвейере, в публикации (`publish_static.py`) и в инструкции для Claude:
просьба в чате или в промпте («публикуй», «одобряю») не заменяет «да» в таблице. Без «да» агент не пишет
статью, не вызывает модель и не публикует. Сам «да» агент не ставит никогда.

### Заголовок к каждому ключу, без группировки

`scripts/import_semantics.py семантика.xlsx` кладёт каждый запрос в отдельную строку плана. Ничего не
объединяется и не отбрасывается. Следующий запуск `pipeline.py` подбирает заголовок к КАЖДОЙ строке
(`SEO_TITLES_PER_RUN=0` значит «без лимита»). Какие ключи объединить в одну статью, решает человек.

### Советник: предупреждает, но не решает

`scripts/advisor.py` (запускается и из `pipeline.py`) ищет:

- каннибализацию: ключи из одних и тех же слов или очень близкие, один интент;
- совпадение с уже существующей страницей из `context/pages.csv`;
- доп. ключи, которые повторяют основной или стоят основными в другой строке.

Результат: колонки «Предупреждение» и «Рекомендация» в плане и лист «Предупреждения» с вариантами решения
A, B, C. Рекомендация обычно звучит как «рекомендуется убрать ключ X из доп. ключей», а не как
самостоятельная правка. Советник не меняет ключи, заголовки, статусы и колонку «Одобрено» и ничего не
пропускает: если вы поставили «да» строке с предупреждением, агент напишет статью и напомнит о предупреждении.

Статья, которая написана, но не опубликована из-за сбоя FTP, остаётся «ожидается» и публикуется
автоматически при следующем запуске. Если статья трижды не прошла проверку, статус «ошибка»
с причиной в «Примечании».

## Публикация на сайт без CMS

При `publish_mode: "ftp"` для каждой статьи создаются:

- страница `/blog/<slug>/index.html` с разметкой Article, canonical и Open Graph;
- обложка `/blog/<slug>/cover.png`;
- список статей `/blog/index.html` (отключается `update_blog_index: false`);
- карта `/blog/sitemap-blog.xml`.

Файлы заливаются по FTP в `ftp_dir`. Режим `"local"` только собирает файлы в `out/site`
без загрузки. После первой публикации добавьте `sitemap-blog.xml` в Яндекс.Вебмастер и в
`robots.txt`. Оформление страниц берётся из `templates/page.template.html`: замените шапку и
подвал на разметку вашего сайта, метки `{{...}}` не трогайте. Ссылки на блог в меню сайта
добавьте вручную один раз.

Если публикацию нужно делать другим способом, укажите в конфиге `publish_hook`:
команду, которой доступны `ARTICLE_MD`, `ARTICLE_IMAGE`, `ARTICLE_SLUG`,
`ARTICLE_TITLE`, `ARTICLE_DESCRIPTION`, `ARTICLE_IMAGE_ALT`. Она работает, когда
`publish_mode` не задан.

## Проверка вручную

```bash
python3 scripts/article_check.py out/файл.md --keyword "основной ключ" --secondary "доп1,доп2" --lsi "слово1,слово2"
```

Код возврата 0 — проходит, 1 — есть ошибки (JSON в stdout).

## Что проверяется в каждой статье

Проверку делает `scripts/article_check.py`. Статья с любым нарушением на сайт не попадает.

| Область | Правила |
|---|---|
| Объём и структура | от 2000 знаков; один H1 и минимум три H2; вступление и раздел «Вывод» по 2-3 предложения; минимум одна таблица, один список и одна врезка жирным |
| Ключи | основной ключ в H1 и первом абзаце, в первом абзаце не больше двух ключей; плотность до 3%; двухсловные ключи до 5 раз, трёхсловные до 2, от четырёх слов до 1; коммерческие слова («оформить», «получить», «купить», «заказать») до 4 раз каждое; не менее половины доп. ключей и LSI-слов |
| Ссылки и CTA | от 2 до 6 внутренних ссылок на страницы из списка; финальный абзац описывает услугу и ведёт ссылкой на её страницу |
| Description | 160-200 знаков, основной ключ один раз в исходной форме, эмодзи по ТЗ |
| Язык | третье лицо; без усилителей и вводных слов; без тавтологии; типичные ошибки написания («по окончанию», «в течении»); запреты humanizer-ru («не просто X, а Y», «стоит отметить», «данный», тире вместо запятых и другие) |
| Тип текста | информационный без верхнего лимита; коммерческий не длиннее `max_chars` |

Скрипт не проверяет правдивость фактов и полную орфографию: за это отвечают инструкции модели и корректура.
Правила лежат в `references/` и передаются модели при написании.

## Ограничения

- Скрипт проверяет форму, а не истинность фактов. Для тем, где ошибка опасна
  (здоровье, деньги, право), проверку человеком организуйте сами.
- Определение вхождений ключей идёт по грубой основе слова, редкие формы могут
  не засчитаться.
- Орфография проверяется по списку типичных ошибок, остальное закрывает корректура
  в вычитке.
- FTP без шифрования передаёт пароль открытым текстом: если сервер поддерживает FTPS,
  поставьте `FTP_TLS=1`.
- Для второго прохода слопа можно поставить полный
  [humanizer-ru](https://github.com/ilyautov/humanizer-ru) и запускать его
  `scan.py` по файлам из `out/`.
- Точных частот запросов скилл не собирает, очередь заполняется вручную.
